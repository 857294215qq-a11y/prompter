# V3 Motion System (Task Group 5) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One easing curve and four duration tiers drive every transition and animation; popovers open from their anchor, small controls slide and press, jumps scroll on the shared curve, the countdown and text changes animate, and reduced motion keeps only a 120ms fade.

**Architecture:** Tokens live in CSS (`:root` in `ui-v3.css`). JS reads them through one helper `motion(name)` in `ui-v3.js` (falls back to the same values when stylesheets are not loaded, as in jsdom) and through `cubicBezier()` in the engine for the scroll curve. `animateSurface` in `ui-v3.js` gains a kind (`surface` / `popover`) instead of one fixed recipe. Branch `v3-motion` is stacked on `v3-tooltips` (PR #6 still open).

**Tech Stack:** Vanilla JS classic scripts, CSS, Web Animations API, jsdom 26 + node:test.

**Spec:** `openspec/changes/v3-design-parity/specs/motion-system/spec.md`, decision 7 in `openspec/changes/v3-design-parity/design.md`.

## Global Constraints

- Tokens (exact): `--ease: cubic-bezier(.32,.72,0,1)`; `--dur-surface: 240ms`; `--dur-popover-in: 200ms`; `--dur-popover-out: 150ms`; `--dur-control: 180ms`; `--dur-text: 160ms`; `--dur-scroll: 320ms`; `--dur-beat: 240ms`; `--dur-tip: 120ms`; `--dur-reduced: 120ms`.
- No transition or animation outside the reduced-motion branch may hard-code a duration or curve (CSS or JS).
- Popover: scale .96 → 1 with opacity, `transform-origin` at the trigger. Press: scale .97. Countdown beat: scale 1.15 → 1 with opacity. Text changes: opacity / background only, no movement.
- Reduced motion: every change is a 120ms opacity fade at most; no translate, scale or smooth scroll; all end states identical to the default mode.
- `npm run stamp` before each commit touching `index.html`, scripts or styles.

## Review Focus

1. Rapid open/close of a popover while its 200ms open is running — the close must cancel it and leave it hidden (not stuck at opacity .5). (Task 2 test `rapid toggles settle hidden`.)
2. Voice follow moving the reading position — never uses the 320ms scroll animation. (Task 3 test `voice follow never animates`.)
3. Countdown cancelled mid-beat (pause during countdown) — no animation leaks onto the next start. (Task 3 test `pausing during the countdown leaves no running beat`.)
4. Reduced motion toggled while the reader is open — the engine's `reduceMotion` is read once at load; jumps must follow the live preference. (Task 4 test `reduced motion is read live`.)
5. Editor re-render on blur — must not re-flash every cue and bold run; only the one just changed animates. (Task 3 test `only the changed run flashes`.)
